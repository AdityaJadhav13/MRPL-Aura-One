important states have been checked (directive §43) — not when the code is generated.

## Phase 2 — Simulation-mode worker workflow

**Recommended boundary.** In scope:

- The persisted workflow state machine: assign → verify → activate → run → close → result →
  history, every transition written to storage before the UI advances.
- Interruption recovery: kill the app at each step and resume correctly.
- Riverpod introduced here, because this is the first state worth managing.
- Simulated badge specimens (blank, low, mid, high, saturated, expired, damaged) driving the
  real result state machine, all in the `simulated` data domain and visibly marked.
- Refusal copy for every reason code — what happened, why it matters, what to do.
- Clock-integrity recording: wall clock, monotonic elapsed, divergence warning.

Explicitly **out** of scope, to keep the boundary honest:

- No camera and no image handling. A simulated scan picks a specimen; it does not photograph
  anything. (Phase 3)
- No Drift yet. Phase 2 persists through a single narrow storage interface so Phase 6 can
  put SQLite behind it without touching the workflow. A simpler store is sufficient to prove
  interruption recovery.
- No Supabase, no auth, no sync. (Phases 7–8)
- No dose inference, no calibration, no colour science. A simulated specimen carries its own
  declared status and value; nothing is computed from an image.
- No officer or admin surfaces. (Phase 9)

**Gate:** kill the app at each step and confirm it resumes correctly; every refusal state
reachable and explained; nothing in the `simulated` domain renders without its marker.

## Phase 3 — Camera scanner and deterministic CV
Capture UI with live guidance overlay and auto-capture arming. Then, in
`measurement-engine`: quality metrics, fiducial detection, homography, rectification, ROI
sampling. Synthetic fixtures generated by `tools/`.
**Gate:** fixture suite green; guidance behaves correctly on a real phone in bright sun and
in a dark room.

## Phase 4 — Colour calibration pipeline
Linearisation, correction fitting, held-out patch validation, CIELAB, ΔE₀₀. This phase
includes the dossier's **V0 experiment**: printed colour targets photographed on several
phones under several illuminants, becoming real fixtures.
**Gate:** independent-phone agreement measured and recorded; `REFERENCE_PATCH_FAILURE`
triggers correctly on glare and on a damaged patch.

## Phase 5 — Measurement engine interface
Calibration model types, loading, checksum verification, version and domain gating, monotonic
interpolation, uncertainty propagation, the validity engine, the adversarial false-reassurance
test suite. No real coefficients — a mock model exercises the machinery.
**Gate:** no input produces a valid result with a null dose; no refusal carries a dose.

## Phase 6 — Local offline persistence
Drift schema, constraints, triggers, migrations with tests. Workflow moves onto real storage.
**Gate:** constraint-violation tests all fail as intended; migration tests green.

## Phase 7 — Supabase backend, auth, RLS
Three projects, schema migrations, RLS policies, pgTAP tests, auth, identity/exposure split,
private evidence bucket with signed URLs.
**Gate:** cross-organisation and cross-role read attempts return zero rows, proven by test.

## Phase 8 — Offline synchronisation
Outbox with idempotency keys, backoff, sync state UI, supersession handling.
**Gate:** double-sync produces one server row; network dropped mid-push recovers cleanly.

## Phase 9 — Safety officer functionality
Exceptions queue, worker roster, exposure history, badge and lot status, scan review with
evidence image, export with method and version fields.
**Gate:** every exception class reachable and actionable.

## Phase 10 — Real laboratory calibration ingestion
`tools/` CLI to ingest lab datasets, fit monotonic models, compute residuals and uncertainty,
emit a signed versioned model. **Blocked on lab data.**

## Phase 11 — Device validation
Low, mid and high-end Android. Measure agreement, latency, rejection rates. Record results.

## Phase 12 — Hardening
Security review, performance profiling, accessibility audit, Sentry, localisation if in scope.

## Phase 13 — Play Store internal release
Research **current** Play requirements at that time. Signing, data safety declaration, camera
disclosure, privacy policy, internal track.

## Phase 14 — Controlled field pilot
Under site authorisation only, per dossier V8.

## Sequencing note

Phases 1–9 are all buildable now and do not depend on the laboratory. Phase 4's V0 experiment
is the highest-value thing the software team can do in parallel with chemistry work, because
it produces real evidence on the phone reader — software's own question — rather than more
simulation.

Do not skip to Phase 13 to make the app look finished. An app that ships a number without
Phase 10 is the exact false-reassurance failure this architecture exists to prevent.
